# 桌宠网页搜索

两套桌宠除生日外的用户回答题目均提供按需使用的 `web_search` 工具，包括称呼、偏好、心情与近期生活。搜索器只调用 DeepSeek 官方 Search，不再包含 DuckDuckGo/Bing 抓取或旧供应商回退。人设、表情池、`/pet/reply` 的 JSON/SSE 契约不变；主页配套调整多轮等待，并把称呼从固定回复接入 AI，生日仍为本地固定回复，失败时继续使用原有本地句库。

## Key 与模型

Search 与模型 API 共用 DeepSeek 官方 API Key，无需申请搜索专用 Key。

- `SLEEPY_AI_SEARCH_API_KEY` 非空时，作为独立的官方搜索 Key。
- 未填写时，仅当 `SLEEPY_AI_ENDPOINT` 是 HTTPS 的 `api.deepseek.com`（默认端口、无用户名/密码）才复用 `SLEEPY_AI_API_KEY`。
- 第三方模型中转 Key 不会发送给 DeepSeek；此时需要单独填写官方搜索 Key，否则不向模型提供搜索工具。
- 官方模型端点默认启用 `SLEEPY_AI_MODEL_AUTO=true`：首次使用通过相同官方 Key 请求 `GET https://api.deepseek.com/models`，按接口顺序选取 ID 或显示名称包含 `flash`（忽略大小写）的第一个有效模型；没有匹配项时使用列表第一个有效 ID。不是按价格或版本号排序，因此无 Flash 时不保证费用相同。
- 列表选择缓存 6 小时，多个线程首次请求合并为一次；socket 超时最多 3 秒，响应分块读取并检查时间预算，最多 128 KiB，不跟随重定向。一次阻塞读取仍可能占用 socket 超时，因此 3 秒不是端到端时限。失败沿用最近选择，冷却 60 秒再尝试；首次失败使用 `SLEEPY_AI_MODEL`，默认 `deepseek-flash`。缓存位于各长期 provider 实例内，重启后重新发现。
- 同一回复的全部工具轮次固定使用同一个模型，不在中途切换。第三方端点始终使用配置的模型，不把代理 Key 发送给官方模型接口。`SLEEPY_AI_MODEL_AUTO=false` 可以固定模型；官方的稳定别名 `deepseek-flash` 本身也是较简单的免版本维护方案。
- 默认关闭思考模式。评论审核共用模型客户端，所以同样采用此选择策略，但不会获得桌宠的搜索工具或人设。

参考：[官方搜索指南](https://api-docs.deepseek.com/zh-cn/guides/search/)、[模型列表接口](https://api-docs.deepseek.com/api/list-models/)、[模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。截至 2026-10-26，Search 成功且有结果按 5 元/千次计费，模型 token 费用另计。运营计数不能代替官方账单。

## 一次回复的流程

1. 校验问题白名单和原有聊天限流；除生日外的 10 个用户回答题目均可搜索，切换主题、播放音乐等本地动作不调用 AI。
2. 系统提示明确告知本轮工具可用与否。普通偏好和心情陪伴不强制搜索；需核实公开知识时提取相关主题。提示词禁止将姓名、完整出生日期、联系方式、住址、个人经历或历史回答用于搜索用户本人；确需当地公开信息可使用城市名。这是模型行为约束，不能视为语义隐私过滤器。
3. 一次回复最多接受 3 次工具调用，支持逐轮改换关键词和单轮多个查询，最多 4 次模型请求。超出上限的调用不会执行；重复查询消耗本轮次数但不再次出站。不认识作品时仍有首轮措辞兜底搜索，心情、称呼等个人回答不会被直接拼成兜底查询。
4. 规范化查询，先读取 SQLite 缓存。缓存键是版本、返回条数和查询的 SHA-256；不保存原始查询。
5. 缓存未命中：通过事务占用同查询租约并原子预留当天出站请求额度，再访问固定的官方 HTTPS 地址。
6. 返回前 3 条（可配置 1～5 条），每条标题最多 200 字符，优先长摘要、回退短摘要，摘要最多 800 字符；附带来源 URL、站点和日期。无全文抓取，不把搜索 URL、摘要和工具参数作为 SSE 事件发给浏览器。
7. 结果作为不可信资料传给模型，空结果可以换关键词再查；搜索报错立即结束检索并让模型保守作答。到达 3 次上限后不再提供工具。若模型仍只返回工具请求而没有答案，则按既有失败协议交给前端本地兜底，绝不发起第 4 次搜索。

主页每次收到有效 `thinking` / `searching` 进度会重置 35 秒无进展超时，单回复硬上限 90 秒；用户开始新回答、切换桌宠或离开页面仍可取消。无需等满上限，有最终回复就立即展示。生产若自定义更长的模型/搜索超时，仍可能被前端总时限截断；这些上限不是响应时长承诺。

仅改为搜索供应商不会消除模型幻觉；现有措辞识别兜底不是语义准确率保证。应以实际作品查询、回复质量和运行日志观察效果。

## 缓存、并发与预算

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| `SLEEPY_AI_SEARCH_ENABLED` | `true` | 关闭后不提供搜索工具 |
| `SLEEPY_AI_SEARCH_TIMEOUT` | `6` | 上游网络超时秒数，可配置 2～15 |
| `SLEEPY_AI_SEARCH_MAX_RESULTS` | `3` | 返回 1～5 条 |
| `SLEEPY_AI_SEARCH_CACHE_TTL` | `21600` | 正结果缓存秒数，允许 60～86400 |
| `SLEEPY_AI_SEARCH_CACHE_MAX_ENTRIES` | `1024` | LRU 缓存容量，允许 1～10000 |
| `SLEEPY_AI_DAILY_SEARCH_LIMIT` | `100` | 每个 UTC 日最多预留的出站搜索次数；0 禁用工具 |
| `SLEEPY_AI_SEARCH_DB` | `pet_search.sqlite3` | 相对 `SLEEPY_DATA_DIR`；支持绝对路径 |

空结果缓存 5 分钟。缓存命中不消耗搜索额度，额度用尽或上游冷却期间仍可复用已有缓存。关闭开关或限额设为 0 则完全停用搜索，包括缓存。

同一数据库的多个线程/进程共享预算与缓存；同查询用租约去重，等待不超过配置的搜索超时，超时即降级，不再额外发出上游请求。进程崩溃后租约自动到期，但预留额度不退还。仅搜索状态支持跨进程一致性，不代表整个 Sleepy 已支持多实例部署；数据库应放在本机持久磁盘，不使用网络文件系统。

所有出站尝试（含失败、超时、进程崩溃）均保留预算，不自动重试，因此实际收费通常低于“attempts × 单次价格”。HTTP 401/402/403 冷却 60 秒，429 优先采用秒数形式 Retry-After 并限制在 5～300 秒，其他 HTTP/网络/协议错误短暂冷却 5 秒。冷却共享且持久；修正密钥后最多等待一分钟。SQLite 故障时不绕过预算请求供应商。

网络有 socket 超时，响应流另检查读取截止时间，并最多读取 512 KiB；不跟随 HTTP 重定向，不把 Bearer Key 转发到其它地址。同一 socket 读取可能占用剩余超时，因此该参数不是端到端回复 SLA。回复还包括最多四次模型调用。

## 运维与发布

新增文件 `pet_search.sqlite3` 及其 WAL/SHM 已被 Git 忽略，代码发布包不包含数据库。发布、月度重启、回退代码时保留它；如果删除或恢复旧数据库，会重置/回退预算。活跃数据库备份使用 SQLite backup，不能仅复制主文件而漏掉 WAL。

在项目根目录、使用生产相同的环境变量与虚拟环境执行：

```sh
python -m pet_ai.search_status
```

该命令不调用外部 API、不输出密钥或原始查询，展示最近 31 个 UTC 日的 attempts、successes、empty、errors、cache_hits、blocked。第一次运行会创建数据库。PM2 日志会包含 `pet_search outcome=... elapsed_ms=...`，可定位配置、余额、限流、存储和超时问题。未完成请求可能只有 attempts 没有对应完成计数，不将其误报为免费调用。

部署仍使用 `pnpm ship`；现有官方 Key 可直接复用，新增配置都有默认值，通常无需同步 `.env`。自动模式下，已有 `SLEEPY_AI_MODEL` 用作冷启动发现失败时的备用模型，模型发现成功后使用列表选择；不会修改 `.env`。关闭自动模式后才始终使用配置值。任何模型/搜索配置变更需重启，PM2 环境变量仍优先于 `.env`。先发布后端，再发布主页以启用称呼 AI 和多轮超时支持。

本地验收：

```sh
python -m unittest discover -s tests -p 'test_pet*.py'
pnpm ship:check
```

测试覆盖 HTTP 契约、重定向、无效响应、响应大小、超时、Key 选择、缓存过期/容量、并发和跨进程配额、崩溃租约、冷却、日志脱敏、全部题目的工具能力、三轮/批量/重复工具调用、模型发现/缓存/故障回退/同轮固定及 JSON/SSE。主页测试覆盖多轮进度、无进展超时、总时限、取消及本地兜底。
